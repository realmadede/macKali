Toolkit Integration & Troubleshooting

App-Specific Traffic Lights Setup

While GTK 4, Libadwaita, and GTK 3 applications display circular traffic lights automatically, browsers, Electron suites, and Qt apps require one-time toggles to adopt native system window controls.

Google Chrome, Brave & Chromium

Chromium-based browsers draw custom titlebars by default with their own window buttons. To enable native macOS traffic lights:

  • Method 1: Right-click an empty space in the top tab strip (beside the + button) and check “Use system title bar and borders”.
  • Method 2: Go to Settings → Appearance and toggle on “Use system title bar and borders”.
  • Result: Traffic lights immediately move to the top-left in authentic macOS Red, Yellow, and Green circles.

Mozilla Firefox & LibreWolf

Firefox can be switched from internal CSD tab drawing to full native GTK titlebars in three clicks:

  • Step 1: Right-click any blank area of the navigation or tab bar and select “Customize Toolbar…”.
  • Step 2: In the bottom-left corner of the customization screen, check the “Title Bar” checkbox.
  • Step 3: Click “Done” to apply. Firefox will now use the native system header with top-left circular controls.

VS Code, VSCodium & Cursor

Modern code editors render an Electron custom titlebar by default. Switching to native window styling restores system controls:

  • Step 1: Open Settings with Ctrl + , (or File → Preferences → Settings).
  • Step 2: Search for window.titleBarStyle in the search bar.
  • Step 3: Change the value from custom to native. Restart or reload the editor window to enjoy authentic window controls.

Discord, Slack, Obsidian & Electron

Electron applications offer native window options or Wayland ozone platform flags for clean window integration:

  • In-App Setting: Look under Appearance or Window settings and switch the title bar style to Native.
  • Wayland Native Launch: Start the app with --enable-features=UseOzonePlatform --ozone-platform=wayland for native compositor integration.
  • Frameless Window Toggle: In Obsidian, switch Window frame style to Native (under Appearance → Window).

Sandboxed Flatpak & Snap Applications

Containerized applications are sandboxed from reading host desktop configurations by default. Grant theming permissions with:

  • Flatpak Theming: Run flatpak override --user --filesystem=xdg-config/gtk-4.0:ro to grant GTK and traffic lights stylesheet access.
  • Snap Theming: Connect the theme slot with sudo snap connect <app>:gtk-3-themes whitesur-gtk-theme.
  • GUI Management: In Flatseal, select any app and toggle on Filesystem → User Configuration read access.

Qt 5 & Qt 6 Applications (Wireshark, VirtualBox)

Qt applications leverage the Kvantum engine for macOS widgets while aligning buttons to the top-left:

  • Interior Widget Theming: Run ./scripts/providers/qt-provider.sh --install to style buttons, tabs, tables, and dialogs.
  • Top-Left Controls: Window buttons automatically adopt top-left macOS placement (close,minimize,maximize:).
  • Server-Side Decorations: Launch via QT_QPA_PLATFORM=xcb <app> to route titlebars through Mutter on Xwayland.

macKali is architected for rolling distributions. It never pins packages or blocks GNOME updates. When your system updates, running ./install.sh --recheck re-evaluates extension compatibility against the new GNOME version and official GNOME Extensions metadata, gracefully skipping unsupported extensions without breaking your themes or wallpapers.

While engineered and optimized for Kali Linux, macKali is built entirely on POSIX shell standards, FreeDesktop specifications (~/.config, ~/.local/share), and standard GSettings/dconf schemas. Because it avoids distro-locked binaries, it works cleanly across Debian (12 Bookworm, 13 Trixie, Testing, Sid), Ubuntu (22.04, 24.04, 24.10), Fedora Workstation (39 to 42+), Arch Linux / Manjaro, and Pop!_OS. On desktop environments: GNOME Shell (42 to 50+) offers the full experience; XFCE is supported via built-in xfwm4 fallback hooks; and KDE/Cinnamon receive cursor, wallpaper, and GTK application theming.
By default, macKali installs the top-left circular traffic lights for all GTK3 and GTK4/Libadwaita applications, isolated hover glow, WhiteSur HiDPI cursors, rootless user safety, and automated backup snapshots. Optional settings and presets (--preset minimal|balanced|full, --mode dark|light, --extensions, --wallpaper) let you opt in to the centered floating bottom dock, dual 4K day/night wallpapers, 3D window effects (Magic Lamp, Wobbly Windows), and standalone modular providers.
This is due to the architectural division between interior widget styling and window decorations on Wayland. The Qt Provider (qt-provider.sh) configures the Kvantum (QStyle) engine, which styles all interior controls (menus, buttons, tabs, tables, packet lists) in WhiteSur macOS style. On GNOME Wayland, however, the window manager does not provide server-side window frames; Qt 6 uses its internal Wayland decoration client with hardcoded monochrome icons (_, □, ✗). macKali guarantees the buttons are on the top-left in macOS order (close,minimize,maximize:). If server-side decorations are desired, launching via Xwayland (QT_QPA_PLATFORM=xcb wireshark) routes window framing to Mutter.
GNOME Shell retired the global application menu infrastructure in GNOME 40+. Third-party global menu extensions are notoriously fragile and frequently break across GNOME point updates. macKali prioritizes system stability and security tool availability: keeping Kali's native top panel ensures your network monitors, VPN controls, workspace switchers, and Kali security menus remain rock-solid and accessible.

macKali is designed for near-instant installation without bloated compile cycles. Installing only the WhiteSur cursors takes approximately 2 seconds. Running the complete interactive wizard with the recommended Balanced preset takes 15 to 30 seconds (including wallpapers, dock styling, and verified extension bundle fetching). If extension archives are already cached, applying the complete desktop environment takes under 3 seconds. Single-command rollback to original defaults takes 1 second.
macKali features an automated in-app release update checker. Every time you run the installer or customization wizard, macKali performs an unobtrusive 2-second check against the official GitHub Releases API. If a newer release or security patch is available, an alert banner is displayed with instant upgrade instructions. You can also run ./install.sh --check-update at any time. When Kali Linux upgrades GNOME, running ./install.sh --recheck re-evaluates extension compatibility dynamically without reinstalling your wallpapers or themes.
Yes, macKali runs completely inside VirtualBox, VMware, and QEMU/KVM. For the smoothest experience, enable 3D Acceleration in VirtualBox VM settings (allocate 128MB or 256MB VRAM) and install guest integration (sudo apt install -y virtualbox-guest-x11). The recommended preset for virtual machines is Balanced (or Minimal for 2GB–4GB RAM VMs). macKali contains zero telemetry, zero tracking, zero background daemons, and zero credential scrapers. It runs rootless in user space. During installation, it performs a 2-second check against the official GitHub Releases API (disable with --no-update-check for air-gapped environments). It sets user configuration files (~/.config/gtk-4.0/gtk.css, ~/.config/environment.d/10-mackali-qt.conf) and applies standard GSettings D-Bus window layouts. It never touches shell configs (~/.zshrc), Metasploit, Wireshark packet engines, proxies, or network interfaces.
